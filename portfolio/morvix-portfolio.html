02 · Overview

The problem, and our answer

The problem

Children can meet harmful material inside pages that are otherwise fine: a sentence in a comment, an image in an article, a clip in a feed. A filter that only blocks websites cannot see it, and parents rarely know what their child came across.

Our answer

A browser extension reads the content a child is about to see and sends it only to a MORVIX server running on the same computer. Local AI models score it, the parent's rules decide whether to allow, warn or block, and the parent reviews what happened in a dashboard.

No outside moderation service is ever called. Google Sign-In is optional and used for identity only.

Who it is for

  • The parent or guardian owns the account, sets the rules and reviews alerts.
  • The child browses normally in a protected Chrome or Edge browser.
  • Evaluators and advisers can test it on built-in demo pages.

In scope

  • Text, images and playing videos on web pages
  • Allow, warn and block rules per category and per website
  • Detection history, alerts and analytics
  • Optional audio checking (off by default)

Out of scope

  • Monitoring outside the supported browser
  • A native mobile app or cloud deployment
  • Removing content from other platforms' servers
  • Crisis intervention

03 · Features

What MORVIX does

Every piece of content gets a category and a confidence score. The parent's policy turns that score into one of three outcomes.

Allow

Nothing to see

Content scores below the flag threshold. It is shown, and no event is recorded.

Warn / Flag

Held for review

Scores at or above the flag threshold (default 0.50). Hidden from the child by default, or shown with a warning if the parent prefers, and recorded for review.

Block

Covered

Scores at or above the block threshold (default 0.80) in a category the parent has set to block. The page is replaced by a MORVIX screen with a Go back button.

Three protected categories

Graphic ViolenceGore, injury and killing described or shown in detail.
Threat LanguageThreats or intimidation aimed at another person.
Self-harm IndicatorsStatements of wanting to die or self-injury.

Content it checks

TextUp to 3,500 characters of visible page text, plus the search query on results pages.
ImageEvery image of at least 100 × 80 px, up to 40 per page view.
VideoA frame every 5 s of a playing video, up to 2 videos per page.
AudioOptional: a local transcript checked as text.

Parent dashboard

  • Sign-in with password (email code verification) or Google
  • Detection history, alerts and analytics
  • Rules per category and per website
  • Sensitivity slider from 1 to 10
  • Extension pairing with a single-use, 10-minute code
  • A Test classifiers page for trying any text or image

04 · Architecture

How it works

One local server process hosts the API, the dashboard and the AI models. Nothing leaves the computer.

From page to decision

  1. The content script extracts what it can read: the text, eligible images and frames of playing videos.
  2. The extension's service worker sends it to /api/v1/extensions/analyze with its paired credential.
  3. The server checks the parent's policy: is protection on, and is this content type enabled?
  4. The classifier ensemble returns a score per category; the highest becomes the result.
  5. The policy engine applies website rules and thresholds and returns allow, warn or block.
  6. Warn and block results are stored as events and alerts; the content itself is discarded.
  7. The extension shows or hides the content, and the dashboard shows the stored event.

05 · Pre-access protection

Stopping it before it is seen

Our rule

While something is blurred or covered, MORVIX is still deciding. With the default settings, anything the classifiers flag or block is never shown to the child.

Images and videos

A stylesheet blurs all media from the first moment the page loads. Images are checked two at a time from the top of the page. Allowed media is revealed; flagged media stays blurred, unclickable and paused, with a small "MORVIX hid some content" note.

Page text

The page sits behind a "MORVIX is checking this page…" cover until a fast first pass answers, about 0.5 s when warm. The full check with every engine follows and can still hide the page.

Search queries

On Google, Bing, YouTube and other results pages, the query is checked on its own with every engine. In our browser test a "gore" search was replaced by the MORVIX screen 1.7 s after loading, before any result appeared.

Never stuck

If the server cannot be reached, content is released at once. Anything with no answer after 20 s is shown so browsing never freezes. Website block rules from the last synced policy still work offline.

Making it fast under load

In a real Chrome session, dozens of thumbnail checks crowded out the page-text check, and verdicts took 45 s. We changed the server to run one model job at a time by priority, with the cover's check first.

The local classifier ensemble

How text is fused

  • Threat and graphic violence take the highest score across engines.
  • Self-harm votes are halved when the text has no first-person reference.
  • A strong first-person self-harm signal lowers the threat and gore scores.
  • A keyword hit that no model supports is halved.
  • News, fiction and prevention text is damped (models × 0.5).

Guards on images

  • Flat-colour images skip the models; a plain colour once scored 0.73 "violence".
  • Images with no photographic detail skip the ViT model; gradients had scored up to 0.89.
  • A failed analysis is never treated as safe.

08 · Trade-offs

Sensitivity and long pages

Parents choose a sensitivity from 1 to 10. Higher levels catch more harmful content but also hide more harmless text. We measured every level on the held-out set.

Level 6 uses a flag threshold of 0.50 and a block threshold of 0.80, the same defaults as the held-out evaluation.

The buried-sentence test

Our test sentences are short, but real pages are long. We hid each of 48 harmful sentences in the middle of a 3,400-character harmless page and checked whether MORVIX still found it. Scoring the page in 300-character windows, each judged on its own text, more than doubled what we found.

10 · Trust

Privacy, security and limits

What we store

For each warn or block: the page address, content type, category, confidence, action, model, response time and review state.

What we never store

Page text, images, video frames or audio transcripts. Content is scored and discarded.

How accounts are protected

  • Passwords hashed with PBKDF2-SHA256, 310,000 iterations
  • New accounts confirm their email with a single-use 6-digit code
  • Sessions and extension credentials are random tokens, stored hashed
  • Pairing attempts are throttled; codes expire in 10 minutes
  • Repeat detections within 10 minutes reuse one event

What MORVIX cannot see

Inside frames

Cross-origin iframes, closed shadow DOM and images inside frames.

Protected media

DRM or cross-origin video, and CSS background images.

Outside the browser

Other apps and devices. It is content protection, not device surveillance.

An honest status

MORVIX is a student prototype. Our text results come from 160 short synthetic English sentences, and image and video detection have not been evaluated yet. It is not a dependable safety or crisis-detection tool.

11 · Reflection

What we learned

Measure before you claim

Version 2 looked finished, but its AI models had never run. A held-out test set and a check that reports failed engines are what told us the truth.

Keep the test set apart

We tuned on a dev set and wrote the held-out set afterwards. The two scored close (0.920 vs 0.900 accuracy), which tells us our rules were not fitted to the test rows.

Some ideas fail, and that is a result

One-sentence windows found every buried sentence but flagged every harmless page. Int8 quantisation was 35% faster but collapsed the scores. We recorded each one and moved on.

Test where users are

Our demo pages worked, yet in real Chrome page text never reached the server. Only the real-browser test found it.

Fail safe, not silent

A failed analysis is never treated as safe, and a missing model returns "not installed" instead of a fake result.

Next steps

  • Add real, consented examples and Filipino / Taglish text.
  • Have two team members label each row independently and report agreement.
  • Build image and video test sets with properly licensed data.
  • Catch implied threats with no violent words, our weakest area (6 of 30 missed).
  • Try a smaller NLI model to bring a full page under 2 seconds.
